## Research context

**Gold Standard: Duolingo — the habit-loop + engagement-first monetisation benchmark.**
Primary source fetched: [How Duolingo reignited user growth (Lenny's Newsletter, Jorge Mazal)](https://www.lennysnewsletter.com/p/how-duolingo-reignited-user-growth). Supporting: [Deconstructor of Fun teardown](https://www.deconstructoroffun.com/blog/2025/4/14/duolingo-how-the-15b-app-uses-gaming-principles-to-supercharge-dau-growth), [StriveCloud gamification analysis](https://www.strivecloud.io/blog/gamification-examples-boost-user-retention-duolingo).

*Patterns to emulate:* (1) retention before monetisation — engaged users (7+ active days) convert far better, so protect the habit loop's integrity; (2) streak mechanics with anxiety reducers (streak freeze ≈ SmartSpeak's grace day — already present); (3) conversion grew 3%→8.8% mostly by optimising *flows and moments*, not price.
*Anti-patterns to avoid:* paywalling the core habit itself; monetisation asks before first value; reward signals that don't fire reliably (broken trust in the loop).

**Paywall timing — sources conflict, resolved for this product.** Upfront-paywall advocates ([PaywallPro](https://dev.to/paywallpro/the-paywall-timing-paradox-why-showing-your-price-upfront-can-5x-your-conversions-4alc)) report 5–6× conversion from day-1 intent capture; post-value advocates ([ContextSDK](https://contextsdk.com/blogposts/the-right-time-to-show-a-paywall-why-smart-timing-beats-a-b-testing), [Adapty](https://adapty.io/blog/high-performing-paywall-2026/), [RevenueCat](https://www.revenuecat.com/blog/growth/guide-to-mobile-paywalls-subscription-apps/)) show the highest-converting paywalls land right after the "aha" moment, and 82% of purchase starts happen on install day. For a $10 one-time unlock with a 3-rep preview, both camps converge on the same move: **make the offer on the results screen of the last free rep** — post-value, same-session, day-1. That is closure theme 3.

**ASO 2026** ([AppTweak](https://www.apptweak.com/en/aso-blog/aso-for-google-play-app-store-optimization-guide-for-android), [Moburst](https://www.moburst.com/blog/app-store-optimization-guide/), [asomobile](https://asomobile.net/en/blog/aso-in-2026-the-complete-guide-to-app-optimization/)): on Play, the app **name and short description carry the strongest keyword weight**; the first 2–3 screenshots decide the install; long-tail natural-language phrasing is rising with AI-driven discovery. SmartSpeak's listing never contained the category head-phrase **"public speaking"** — closure theme 5.

## Ranked recommendations — the plays NOT made tonight

**R0 — Analysis-pipeline resilience (F14). Impact H / Effort L-M / do this first.**
Wrap `finishAnalysis` below the transcription block in try/catch → on failure set a user-facing error and return to `intro` (the audio blob is already in `audioUrl` — offer "type what you said" as the recovery); add `recorder.onerror` → cleanup + error message; wrap the onboarding localStorage pair in the same try/catch discipline as the other 7 keys. Rationale: any exception after transcription currently strands the user on an infinite spinner **during the exact first-session moments that decide retention**. Kept out of tonight's set only because of the 5-theme cap.

**R1 — Warm the Whisper pipeline during the first take (F15). Impact H / Effort M.**
Today the ~50 MB download starts only when the first take's PCM hits the worker. Add an explicit `{type:'warmup'}` message: worker branch calls `getASR()` (and clears `asrPromise` on failure so a real request can retry); client fires it from `startRecording()`. By the time a 60s take ends on wifi, most of the model is local — the first results screen appears in seconds, not minutes. **Do not** post an empty `{}` message as a shortcut: progress/error messages aren't correlated to requests, and a warm-up error event would reject a concurrent real transcription (`transcribe.ts:86-110`). This is why it's an engine change and excluded tonight.

**R2 — A reminder channel (F19). Impact H / Effort H / strategic.**
Zero-backend means no web push. Options, cheapest first: (a) "Add my practice slot to calendar" button (ICS download / Google Calendar template link — zero backend, one evening of work); (b) TWA notification delegation via PWABuilder's local-notification support (worth a spike); (c) a minimal push relay (breaks the zero-backend story — decide deliberately). Duolingo's data says this is the biggest retention lever the app is missing.

**R3 — Screenshots + feature graphic into the listing (F16). Launch blocker.**
2–8 phone screenshots (min 1080px): home path, mid-take with the ring, results with score + "one thing" card, the new last-free-rep moment. The first 2–3 decide the install (ASO research). `store-assets/feature-graphic.png` exists — upload it.

**R4 — Launch checklist rest (F16).** Real SHA-256 into `assetlinks.json` (Play Console → App integrity) → redeploy → verify the URL returns JSON; start the 14-day/12-tester closed test **immediately** (it's the critical path for a personal account); create `pro_unlock` ($10, non-consumable) + license-tester yourself; internal-test the TWA (no URL bar, mic, transcription, purchase, reinstall-restore).

**R5 — Play price experiment once live.** Play Console supports promotional intro pricing on one-time products — a launch-window $6.99 tests elasticity without touching code (the app reads the price only in copy; keep `PRO_PRICE` in sync or read from Digital Goods `getDetails()` — small follow-up).

**R6 — Trim ~18.2 MB of likely-dead threaded ORT wasm** (`ort-wasm-threaded.wasm`, `ort-wasm-simd-threaded.wasm`) after verifying onnxruntime-web never requests them with `numThreads=1` — deploy-size only, users don't fetch them (F15 evidence).

**R7 — Docs/consistency sweep (F17, F18).** README structure list, RELEASE.md assetlinks line, shared `cn()` import, delete unused ui primitives + placeholder `site.links`.

**R8 — Longer-term product plays** (from the growth sweep, in leverage order): (a) soften locked-module price copy until the first rep is done — "Included in Pro" instead of "Unlock · $10" on the 🔒 cards (`train/page.tsx:284-290`, `view.tsx:191,204`) — the fresh-eyes critic's point that the catalogue still shows three $10 asks at 0 reps; (b) a second free-play use per week for free users (re-engagement hook without giving away the curriculum); (c) module-completion "mastered" share card (pure client-side image gen — organic acquisition); (d) a "streak at risk" banner on the home screen in the evening (no push needed, works for daily-open users); (e) copy `store-assets/feature-graphic.png` (1024×500) into `public/` and use it as the OG image instead of the square icon; (f) cloud build with accounts/sync as the eventual unlock for leaderboards & real reminders — a deliberate strategy decision, not a patch.
